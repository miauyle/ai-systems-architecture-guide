# GitHub Pages 内容与主题准备

[返回首页](../README.md) · [完整目录](../docs/README.md)

## 当前状态

正文已集中在 `docs/`，根目录首页承担仓库入口，`docs/README.md` 提供完整分组目录，`navigation.json` 描述与主题无关的章节元数据。

尚未选定主题，没有 Jekyll、MkDocs、VitePress 等构建配置，也没有部署工作流。仓库提交不会自动证明网站已经发布。

## 导航数据

`navigation.json` 使用 `schema_version`、`groups` 与 `reference_pages`。分组项包含 ID、标题和 pages；页面项包含稳定 ID、标题、仓库相对路径和内容摘要。

JSON 是内容目录，尚不是任何框架可以直接读取的配置。选定主题后，将它转换为对应侧栏与路由，检查所有正文链接。首页和目录中的相对链接保持可在 GitHub 使用。

## 主题适配重点

| 项目 | 需要确认的行为 |
| --- | --- |
| 项目子路径 | 所有路由与资源在 `/ai-systems-notes/` 下工作 |
| 分组侧栏 | 章节 ID、标题与 `navigation.json` 一致 |
| 文内目录 | 标题层次与移动端阅读可用 |
| 公式 | `math` 围栏与 GitHub 行内数学被实际渲染器支持或转换 |
| Mermaid | 流程图、状态图和序列图被渲染且不过宽 |
| 链接 | `.md` 相对链接按站点路由转换，锚点有效 |
| 搜索 | 索引知识正文，避免把维护规则当成普通知识页 |
| 版本与来源 | 保留章节交叉链接和参考资料 |
| 可访问性 | 对比度、键盘操作和图片说明可读 |

建立配置后运行真实构建，检查产物，再核对首页、长章、公式、图与子路径。以实际结果区分源码、构建和部署状态。

## 内容层与展示层

主题负责排版与导航，正文负责知识关系。不要为了满足某个主题，将全部 Markdown 改成只能在该框架运行的页面。

若框架需要 front matter、路由或特定公式格式，可使用构建转换或兼容的元数据。新增依赖与部署权限在选定方案后按实际需求处理。

## 仓库更新

从最新 `master` 建临时分支，修改后运行 `python tools/check_docs.py`，向 `master` 提 PR。根据用户已授权的方式核对并合并，再删除本次临时分支。

具体 GitHub 权限边界见[仓库访问说明](github-connection.md)，内容维护见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
