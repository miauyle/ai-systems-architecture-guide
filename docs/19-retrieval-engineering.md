# 19 · 检索系统：从文档到可引用证据

[返回目录](../README.md) · [应用架构](11-rag-and-agents.md) · [Agent 运行时](20-agent-runtime.md)

## RAG 补的是可获取、可更新、可追溯的信息

模型参数不适合承担高频变化的资料、逐用户访问控制和准确出处。RAG 将授权外部资料在请求时取回、组织为上下文，再让生成模型解释。它不改变模型权重，也不保证生成只使用外部证据。

检索任务是把能支持当前问题的资料送入后续阶段。向量相似度只是候选信号，不等于回答正确；整个链路要区分资料是否存在、候选是否召回、是否入上下文以及最终断言是否得到支持。

## 离线对象如何成为可检索的单元

原文应有稳定文档 ID、版本、来源位置、有效时间与权限。解析保留标题层级、表格列和例外条件，分块将它们变成可独立识别的片段，每块仍指回原文，而不是脱离来源的字符串。

分块要平衡自足性和检索粒度。太小会拆开结论与限定条件；太大使相似度稀释、上下文浪费。可把标题路径加入表示、将表格行与列名绑定、按命中块扩展邻接上下文。重叠帮助跨边界信息，但检索后要去重，否则重复证据挤占预算。

关键词索引保存词项与片段关联；稠密索引保存片段向量及元数据；原文存储负责取回可引用内容。Embedding 模型、Tokenization、分块规则和索引版本要匹配，不能升级查询编码器却继续比较未经兼容检查的旧向量。多产物发布与删除传播见[第 15 章](15-data-lifecycle.md)。

## 一次在线查询怎样走到证据集合

| 阶段 | 传递对象 | 需要保持的关系 |
| --- | --- | --- |
| 输入理解 | 原始问题、身份、时间/区域条件、必要历史 | 改写不覆盖用户原意；身份来自可信状态 |
| 候选检索 | 查询文本/向量 + 授权过滤条件 | 候选记录含文档/块 ID、版本、来源通道和排名 |
| 融合与重排 | 去重后的候选及原问题 | 分数可比较性或融合规则明确 |
| 内容取回 | 对应版本的原文块及必要邻接片段 | ID 与实际内容一致，权限仍有效 |
| 证据打包 | 来源标签、完整条件、片段与 Token 预算 | 不能截掉关键否定/例外后仍声称证据完整 |
| 生成与检查 | 问题、证据集合、输出断言及引用 | 引用可解析且语义上支持对应结论 |

这不是要求每次都使用全部技术；小型资料可精确扫描，编号查询可先用关键词。复杂度应由已定位的召回或证据缺口驱动。

## BM25 为什么能找到精确术语

倒排表记录某个词出现在哪些片段及频率，查询访问相关词的列表，累积候选得分，不必逐字扫描全库。BM25 的典型组成是：罕见词贡献较大，词频贡献逐渐饱和，再按片段长度进行归一化。

词频饱和避免一个片段反复写同一词就无限加分；长度归一化避免长文因包含更多词而天然占优。逆文档频率依据集合统计，库更新会影响得分。具体分词、字段权重与参数由实现决定，分数不是“正确概率”。

它适合编号、罕见术语和明确字面条件，但同义改写可能不共享词项。中文切词、代码符号和编号保留会直接影响召回。解释依据：[BM25 综述](https://doi.org/10.1561/1500000019)。

## 双编码器为何适合召回，交叉编码器为何适合重排

双编码器分别将查询和片段编码为向量，离线计算文档向量，在线只编码查询再做相似度搜索。训练可把相关片段拉近、负样本拉远；负样本质量和任务分布影响“接近”的含义。通用句向量不自动等价于问题—证据匹配模型。依据：[DPR](https://arxiv.org/abs/2004.04906)。

交叉编码器把“查询 + 候选片段”共同输入，可在内部直接交互，识别候选是否满足具体限定条件。但每个候选都需一次联合计算，不能像双编码器那样预存一个通用文档分数，因此通常只处理较小候选集。

重排只能重新选择已进入候选的内容；原文没被召回，再强的重排也无法补回。最终目标是回答价值，包括条件完整性与互补性，不仅是主题相近。

## ANN 如何以召回误差换搜索成本

精确向量搜索计算查询到全部向量的距离，资料量大时读流量与算术开销高。ANN 缩小访问集合，结果可能漏掉真实最近邻；需要用精确基线区分索引误差与 Embedding 本身的相关性缺陷。

HNSW 为向量建立多层近邻图：上层较稀疏，先从入口逐步移动到更近节点，再向下进入更密集层；底层维护候选与当前较优结果，扩展邻居直到满足停止条件。搜索宽度控制探索范围，更多探索通常提高召回，也增加向量距离计算与内存访问。

建图的邻居选择、连接数和增量插入影响可达性、内存与构建成本；并非只按向量维度估计。分区索引则先挑若干区域，压缩索引以近似距离减少存储/读取，它们有不同的漏检与精度来源。依据：[HNSW](https://arxiv.org/abs/1603.09320)、[Faiss 实现资料](https://github.com/facebookresearch/faiss/wiki)。

## 过滤既是权限边界，也是搜索条件

召回阶段先限定授权集合可减少无关候选，但选择性很强的过滤可能改变 ANN 探索效率。先搜全库再过滤可能把候选耗在不可见资料上，导致过滤后不足；需要过取、过滤感知索引或独立分区等策略。

无论采用哪种内部路径，未授权内容不能进入下游重排、模型、用户结果或不必要日志。候选 ID 与统计本身也可能敏感，不能只在最后答案阶段隐藏文本。

召回后取回时还应处理权限撤销和文档版本变化。过滤“当前可见”与选择“问题发生时有效”的资料是两个条件，不能只用最新上传时间替代有效时间。

## 融合怎样避免把不同分数硬加

BM25 与向量相似度的量纲不同，直接相加可能由一个通道的分数范围支配。RRF 按候选在各列表中的名次贡献倒数权重，再累加，同一候选被多路靠前找到就获得更多支持。

融合要用稳定片段 ID 去重，并处理候选缺失、重复版本与通道权重。基于名次避开部分分数校准问题，却也丢掉绝对分数差距；两个通道同时找到错误片段不会变成正确证据。原始入口：[RRF 作者版](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)。

## 查询拆分和多跳如何产生下一次检索

省略信息可结合可信对话状态补全，但模型改写可能引入用户没指定的地区、时间或对象，原始问题应保留。多条件问题可拆成子查询，再合并覆盖情况；不是把子答案直接拼接。

多跳中，第一次证据揭示实体、关联或缺失条件，下一次查询使用这些已确认线索。每个结果记录依赖的来源与版本；不同子查询的条件不能互相矛盾。循环要有查询预算和停止条件，不能把不断增加资料误当成已消除不确定性。

若缺少足够线索，应澄清或说明资料缺口，而非让模型用参数知识补成伪引用。动态多步检索的状态与预算可由[Agent 运行时](20-agent-runtime.md)管理。

## 证据打包与断言绑定

上下文预算还要容纳问题、指令、历史和预留输出。优先保留直接支持与必要条件，合并重复内容、补齐引用目标，避免把所有候选都塞进去。长上下文扩大窗口，不消除选择错误，也增加 Prefill 与 KV，见[第 09 章](09-inference-and-memory.md)。

可以为每条关键断言记录支持的来源 ID 与位置。验证分两层：首先检查引用是否属于本次授权证据、版本和位置能否解析；然后检查内容是否真正支持断言的对象、数值、时间与例外。第一层可程序化，第二层可结合规则、模型或人工，并评估验证器自身错误。

“引用真实存在”不证明“引用支持结论”。模型补充的常识和推断应与原文事实分开；证据不足、冲突或只覆盖部分问题时要明确范围，不因为答案流畅就默认支持充分。

## 排错沿对象的变化定位

原文正确但块里丢条件，问题在解析/分块；块存在但未召回，看查询、Embedding、过滤与 ANN；候选正确但被挤掉，看融合/重排/预算；上下文完整但答案错，看生成与断言验证。每层要保留版本和阶段结果，才能归因。

按阶段评估召回、证据覆盖、引用支持和最终任务正确性，不能只给一个端到端评分后靠猜测调整。具体指标见[第 22 章](22-evaluation-and-production.md)。原始 RAG 研究入口：[Retrieval-Augmented Generation](https://arxiv.org/abs/2005.11401)；本文展开的是通用检索应用链路。
