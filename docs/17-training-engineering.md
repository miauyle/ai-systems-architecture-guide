# 17 · 训练目标、梯度与训练系统详解

[返回目录](../README.md) · [预训练基础](07-pretraining.md) · [下一章](18-inference-engineering.md)

## 1. 损失函数怎样改变一个参数？

设一个位置的 logits 为 z，Softmax 概率为 p，真实标签的 one-hot 向量为 y。交叉熵对 logit 的导数为：

```math
\frac{\partial L}{\partial z_i}=p_i-y_i
```

假设概率为 `[0.7, 0.2, 0.1]`，正确答案是第二个 Token，梯度为 `[0.7, -0.8, 0.1]`。梯度下降减去梯度，因此提高第二项 logit，压低其他项。

这解释了「训练提高正确 Token 概率」如何落到一个具体数值更新。大模型中，梯度还要继续穿过输出头、FFN、注意力和 Embedding，才能到达各个参数。

## 2. 手写一次学习过程

[bigram_train.py](../examples/bigram_train.py) 用一个 `V × V` 表实现 `p(下一 Token | 当前 Token)`。它不是 Transformer，但能完整展示：输入查表 → Softmax → 交叉熵 → 手写梯度 → 参数更新。

重复输入同一个 Token 时，多个位置的梯度要累加回同一行。NumPy 代码使用 `np.add.at`；普通高级索引下的 `gradient_table[inputs] += ...` 遇到重复索引时可能无法按预期累加。

训练材料是四个短句，每句包含 BOS/EOS，总计 24 个预测位置。程序从均匀预测开始，初始平均损失约 2.3026，400 次 SGD 更新后约 0.2393；同时用有限差分验证一个参数的解析梯度，误差约 `9.32e-12`。

```bash
python examples/bigram_train.py
```

「天」后面既可能是「花」，也可能是「雨」，最合理的模型分布应保留这种不确定性。训练损失没有降到零，不必然是程序错误。这个模型只依赖前一个 Token，也没有留出测试集，因此这些结果不证明长距离能力或泛化能力。

本例的 BOS 后接「春/夏」、「天」后接「花/雨」，各有 4 个预测位置且各分支等频，共 8 个位置存在二选一不确定性；其他 16 个位置在这个语料中是确定的。对应平均损失的理论下界是 `8/24 × ln(2) ≈ 0.2310`，与训练后的 0.2393 接近。这个下界来自当前数据与模型条件信息，不是所有语言模型的固定值。

## 3. Token 平均与样本平均有什么区别？

两条样本分别有 10 和 100 个有效回答 Token：

- 对所有有效 Token 求平均，长样本贡献约十倍目标数量。
- 先求每样本平均再对样本平均，两个样本总体权重相同。

两者都可能合理，但训练含义不同。梯度累积中，若各微批次有效 Token 数不同，直接平均各微批次损失也可能不等于全局 Token 平均。分布式实现还要核对梯度归约是求和还是平均，避免重复缩放。

## 4. 有效批大小与更新步数

设每张卡微批次 2 条、每条 2,048 个有效 Token，累积 8 次，使用 64 张数据并行卡：

```text
每次更新的 Token 数
= 2 × 2,048 × 8 × 64
= 2,097,152
```

若训练 100B Token，理论上约需 47,684 次更新。这个估算假设长度固定且无无效目标；Padding、Loss Mask、动态打包会改变有效 Token 数。

增大批次会改变梯度噪声和更新次数，不只是「更省时间」。学习率、warmup 和总 Token 预算应一起比较。

## 5. AdamW 保存了哪些状态？

Adam 保存梯度的一阶矩和二阶矩；偏差修正补偿初始零状态。简化形式为：

```text
m_t = β1 × m_(t-1) + (1 - β1) × g_t
v_t = β2 × v_(t-1) + (1 - β2) × g_t²
m_hat = m_t / (1 - β1^t)
v_hat = v_t / (1 - β2^t)
θ_next = (1 - ηλ) × θ - η × m_hat / (sqrt(v_hat) + ε)
```

最后一行是 AdamW 的解耦权重衰减形式。把权重衰减直接当成普通损失的 L2 梯度并经过 Adam 的自适应缩放，会得到不同更新。

是否对归一化参数、偏置使用权重衰减，依训练设计而定；不能把一个优化器名字当成完整配置。

## 6. 混合精度不是一个开关解决所有问题

FP16 的动态范围较窄，常配合损失缩放以减少梯度下溢：先放大损失，反向后再还原梯度，出现非有限值时跳过或调整更新。BF16 动态范围更接近 FP32，但有效尾数更少，仍需注意数值误差。

某些累加、归一化和优化器状态会保留高精度。监控应包括损失、梯度范数、非有限值、学习率及参数/激活尺度，而不只观察显存下降。

## 7. 梯度裁剪与激活重计算

全局梯度范数裁剪把过大的梯度按比例缩小，控制一次更新的幅度。它不会修复错误标签、Attention Mask 泄漏或学习率配置错误。

激活重计算不保存部分中间激活，在反向时重做前向。它用额外计算换内存，涉及随机数、Dropout 和函数副作用的一致性。重计算和「把参数卸载到 CPU」不是同一种方法。

## 8. 分布式状态分片怎样省显存？

| 方案 | 通常分片的状态 | 大致需要的通信 |
| --- | --- | --- |
| 普通 DP | 每卡完整参数、梯度、优化器状态 | 梯度归约 |
| ZeRO-1 | 优化器状态 | 状态相关同步与梯度通信 |
| ZeRO-2 | 再分片梯度 | 梯度归约/分发 |
| ZeRO-3 / FSDP 类方案 | 再分片参数 | 计算前获取必要参数，之后回收 |

具体框架的获取时机、预取和持久化策略不同。状态分片的省内存收益，需要和通信带宽、层大小及重叠效率一起衡量。

## 9. 后训练的目标具体怎么区别？

SFT 对示范回答的目标 Token 计算交叉熵。DPO 使用同一问题的偏好回答对，比较当前策略与参考策略的相对优势。一种常见写法是：

```math
a=\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
```

```math
L_{DPO}=-\log\sigma(\beta a)
```

`y_w` 是偏好回答，`y_l` 是较差回答，β 控制目标尺度。序列概率通常由有效回答 Token 的对数概率求和构成；长度处理、Mask 与数据偏差影响训练行为。

强化学习则从当前策略采样回答，利用奖励和优势估计更新策略。可验证奖励可以来自代码测试或数学答案，但仍要防止模型利用验证器漏洞；验证器通过也不代表解决了所有未测条件。

## 10. LoRA 的参数节省具体有多大？

一个 `4096 × 4096` 矩阵含 16,777,216 个参数。秩 r = 8 的两个增量矩阵分别为 `4096 × 8` 和 `8 × 4096`，合计 65,536，约为该矩阵的 0.39%。

这只比较被适配矩阵的可训练参数；基础权重仍要加载，其他被训练模块、激活和优化器仍占资源。适配器能否合并、合并后是否再次量化，也会影响部署。

## 11. 训练失败怎样排查？

| 现象 | 先核对 | 后续方向 |
| --- | --- | --- |
| 损失异常低但任务很差 | 标签错位、未来信息泄漏、数据污染 | 独立任务评估 |
| 损失不下降 | 梯度是否产生、目标 Mask 是否全空、参数是否更新 | 学习率、数据和初始化 |
| 中途 NaN | 输入异常、全屏蔽注意力行、精度与激活尺度 | 损失缩放、裁剪与高精度算子 |
| 恢复后跳变 | 优化器、调度器、随机状态、数据游标 | 完整检查点恢复 |
| 训练正常但领域表现倒退 | 数据配比、遗忘、过拟合 | 混合数据与领域回归集 |
