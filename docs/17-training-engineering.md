# 17 · 训练系统：优化、并行与恢复

[返回目录](../README.md) · [预训练](07-pretraining.md) · [后训练](08-post-training.md)

## 一次更新是多种状态的共同推进

训练循环读取数据并前向，累积反向梯度，完成必要通信与数值检查，再更新参数、优化器和学习率状态。前向完成不是一次更新完成；微批次完成也不必然改变权重。

| 状态 | 保存什么 | 何时变化 |
| --- | --- | --- |
| 参数 | 当前网络权重 | 有效优化器更新时 |
| 激活/统计量 | 反向所需的当前前向信息 | 每微批次产生、使用或重计算 |
| 梯度 | 当前更新窗口的贡献 | 反向与归约累积，更新后清理 |
| 优化器历史 | 动量、二阶矩、步数等 | 与参数更新一致推进 |
| 数据/随机进度 | 采样游标、随机状态与配比 | 随实际消费和随机操作推进 |
| 检查点 | 同一恢复点的上述状态及版本 | 一致快照并持久提交时 |

推理 KV 属于请求历史，不能替代反向状态。训练与推理的显存预算因此不同。

## 梯度累积如何模拟更大的更新窗口

微批次是一次前向/反向可放入设备的工作，多个微批次可累积到同一梯度缓冲再更新。累积期间参数不变，不能每个微批次都执行 optimizer step 却仍称其为同一次大批次更新。

归一化要明确按样本还是有效监督 Token。若各微批次先按自己的 Token 数求均值，再等权累加，短微批次会被过度加权。要对应全窗口 Token 平均，可按各微批次有效数量加权或汇总损失总和与总计数；跨 DP rank 也需要一致的计数和归约缩放。

名义上常用 `每 rank 微批样本数 × 累积次数 × DP rank 数` 表示全局批次，变长序列下还应记录有效 Token。数值顺序、dropout 和其他按批次运行的操作可能让累积与一次大批次不逐位相同。

## DDP 在反向时怎样同步

数据并行 rank 持有相同参数，消费不同数据，各自完成前向。反向产生局部梯度，通信按对应参数位置聚合，使所有 rank 在更新前得到一致的全局贡献。

实现常把梯度组织成 bucket：一个 bucket 的梯度就绪便发起归约，与后续层反向重叠，而非等全部反向结束再传。所有 rank 必须遵循相容的通信顺序；动态分支或漏参与会导致等待或错误。

累积时可在前几个微批次暂不通信，最后再归约窗口贡献，避免多次重复同步。但需要框架正确的同步控制，不能只省略一次显式函数调用就假设自动反向通信也停止。这里的完整状态复制不同于后面的分片训练。

设计依据：[PyTorch Distributed](https://arxiv.org/abs/2006.15704)。桶大小与反向就绪顺序影响重叠，论文中的特定硬件性能不作为通用保证。

## AdamW 为什么需要历史状态

梯度只反映当前批次。Adam 类优化器维护梯度的一阶移动平均和平方梯度的二阶移动平均，按各参数的历史尺度调整更新；偏差修正与更新步数相关。AdamW 将权重衰减与自适应梯度更新解耦，不应直接混同为把 L2 项加进梯度的所有实现。

这些状态通常采用较高精度，某些混合精度方案还保留主权重；具体格式不是固定“每参数必有若干字节”。冻结参数通常不需要其优化器状态，LoRA 因此减少这部分占用，但仍有基础前向和激活。

恢复时若只加载权重而丢失优化器、调度和步数，接下来走的优化轨迹不同，不是严格继续训练。依据：[Adam](https://arxiv.org/abs/1412.6980)、[AdamW](https://arxiv.org/abs/1711.05101)。

## 混合精度更新的正确边界

参数存储、前向乘法、归约累加、梯度通信和优化器更新可以采用不同精度。FP16 训练常通过 loss scaling 避免小梯度下溢：先放大损失再反向，更新前将梯度还原，检查是否非有限，再做裁剪与更新。BF16 常不需要同样的缩放策略，但仍需稳定归约和异常检测。

梯度裁剪应作用于正确归一化、去缩放后的梯度；分片时范数需覆盖全参数而非仅本地片段。溢出处理要在相关 rank 上一致，否则一部分更新、一部分跳过会使参数分叉。跳过更新时的调度器与步数策略也须明确。

发现 NaN 后先定位首次异常的输入、算子和状态，不能把“换精度”当唯一解释。标签错位、极端数据、归约错误、学习率和坏检查点都可能导致异常。

## 状态分片怎样运行，而不是怎样平均分配

ZeRO 类方案依次分片优化器状态、梯度、参数，分片对象不同，通信也不同。以下跟踪一种典型 fully sharded、按层或模块组织的生命周期：

| 阶段 | rank 的动作 | 内存与通信代价 |
| --- | --- | --- |
| 静止状态 | 持有自己负责的参数/梯度/优化器分片 | 减少常驻复制 |
| 某计算单元前向前 | all-gather 参数分片，形成该单元可计算的权重 | 临时完整权重与通信缓冲占用 |
| 前向后 | 按策略重新分片/释放完整副本，保存或重计算激活 | 不等于保存所有层完整权重 |
| 反向前后 | 必要时再次 gather 参数，产生局部完整梯度，再 reduce-scatter | 将跨数据 rank 的梯度求和并分发到负责的片段 |
| 优化器更新 | 各 rank 用对应分片梯度与历史更新本地参数分片 | 只维护负责片段的优化器状态 |
| 下一次计算 | gather 的是已更新分片 | 所有 rank 必须属于同一更新版本 |

FSDP 的包装粒度、reshard 与预取策略会改变细节。计算一层时预取下一层权重可以重叠通信，但可能同时持有多个完整单元；峰值显存不能只用常驻分片大小估算。梯度累积还可能改变保留梯度的形态与内存需求。

状态分片主要改变状态所有权和临时汇集；TP 则把一个算子的矩阵计算分给多个 rank，在层内交换部分结果。二者可以组合，却不是同一件事。依据：[ZeRO](https://arxiv.org/abs/1910.02054)、[PyTorch FSDP 教程](https://docs.pytorch.org/tutorials/intermediate/FSDP_tutorial.html)。

## 其他并行维度怎样进入训练循环

TP 的前向矩阵切分见[第 10 章](10-serving-and-distributed.md)，训练还要对相应梯度和激活执行反向通信。PP 将微批次激活传给下一阶段，反向梯度沿反向路径回来；交错前向/反向减少气泡，也改变各阶段保存的激活数量与更新时机。

上下文并行分担序列位置，但全注意力查询仍需要有关的其他位置 K/V，要用通信或分块轮转保持全局信息关系；不能把长文本独立切段后声称执行了原来的全注意力。EP 则将 Token 发给专家，反向还需返回梯度并处理专家参数的相应同步。

并行分组按数据、矩阵、层、序列或专家维度定义；有效全局批次只由实际独立数据贡献决定，不能把每一种并行卡数都乘进样本量。通信语义与拓扑见[第 27 章](27-compute-infrastructure.md)。

## 重计算是以额外执行换保存状态

激活检查点只保存部分边界输入，反向需要某段内部状态时重新前向。保存减少，算术、可能的参数 gather 和通信增加。对 dropout 等随机操作要保留相应随机语义，不能重计算出与原前向无关的状态。

减少激活后，权重 gather、通信缓冲或优化器可能成为新峰值。优化显存需要按时间线识别同时存活的对象，而不是逐项估算后只取平均。

## 检查点怎样成为一个可恢复版本

所有分片必须对应同一逻辑更新边界。异步保存可以先固定一致快照再后台写，不能让训练继续修改同一缓冲导致某些片段新、某些片段旧。快照本身需要额外内存和复制，后台存储失败仍要可见。

可恢复提交需要参数、优化器/调度、步数、随机状态、数据游标和配置版本，以及分片清单和完整性检查；未提交的一组文件不应被当作完整检查点。拓扑变化时还需可靠的重分片，不能按旧 rank 文件名随意加载。

检查点机制与数据路径见[第 27 章](27-compute-infrastructure.md)，资产发布见[第 26 章](26-model-lifecycle.md)。故障排查应分别看数据正确性、数值、通信等待、峰值内存和恢复一致性，避免用单一吞吐数字覆盖它们。
