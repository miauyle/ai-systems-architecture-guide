# 17 · 训练系统：优化、并行与恢复

[返回目录](../README.md) · [预训练基础](07-pretraining.md) · [下一章](18-inference-engineering.md)

## 一次更新怎样贯穿系统

前向计算把批次变成目标分布与损失，反向沿计算关系得到梯度，分布式系统将需要同步的梯度或状态汇聚，优化器再更新参数。数据、梯度与优化状态分别具有自己的生命周期。

梯度不是权重的新版本，而是损失对参数变化的局部信号。优化器将这个信号与历史统计、学习率和正则化结合。不同 worker 的梯度如何聚合、何时更新，决定实际训练目标是否与设计一致。

## 批次、微批次与梯度累积

微批次是一次前向反向处理的输入，有效批次是在一次参数更新中合并的数据。梯度累积跨多个微批次保留梯度，之后才更新；数据并行也增加参与该次更新的样本。

累积减少对单次大批次的需求，但不会消除单个微批次需要的激活。有效批次变化还影响梯度噪声与总更新次数，不能只当作吞吐旋钮。学习率、warmup 和训练 Token 预算需要一起考虑。

不同长度与 Loss Mask 使“样本数相同”不等于“有效目标数相同”。动态打包提高有效占比，但必须保留样本边界与损失归一化语义。

## AdamW 的历史状态

Adam 类方法为参数维护梯度的一阶与二阶统计，用以调整更新尺度；偏差修正处理初始状态。AdamW 将权重衰减与自适应梯度更新分开，区别于直接把 L2 项混进梯度。

这些状态是训练显存的重要组成，也决定恢复后的更新行为。只加载权重再从零开始优化器，通常不是原训练的等价继续。哪些参数使用衰减、统计精度和学习率调度都属于完整训练配置。

原始依据：[Adam](https://arxiv.org/abs/1412.6980)、[AdamW](https://arxiv.org/abs/1711.05101)。

## Token 平均与样本平均有什么区别？

样本长度不同时，损失聚合策略会改变各样本的权重：

- 对所有有效 Token 求平均，长样本贡献更多目标位置。
- 先求每样本平均再对样本平均，两个样本总体权重相同。

两者都可能合理，但训练含义不同。梯度累积中，若各微批次有效 Token 数不同，直接平均各微批次损失也可能不等于全局 Token 平均。分布式实现还要核对梯度归约是求和还是平均，避免重复缩放。

## 混合精度不是一个开关解决所有问题

FP16 的动态范围较窄，常配合损失缩放以减少梯度下溢：先放大损失，反向后再还原梯度，出现非有限值时跳过或调整更新。BF16 动态范围更接近 FP32，但有效尾数更少，仍需注意数值误差。

某些累加、归一化和优化器状态会保留高精度。监控应包括损失、梯度范数、非有限值、学习率及参数/激活尺度，而不只观察显存下降。

## 梯度裁剪与激活重计算

全局梯度范数裁剪把过大的梯度按比例缩小，控制一次更新的幅度。它不会修复错误标签、Attention Mask 泄漏或学习率配置错误。

激活重计算不保存部分中间激活，在反向时重做前向。它用额外计算换内存，涉及随机数、Dropout 和函数副作用的一致性。重计算和「把参数卸载到 CPU」不是同一种方法。

## 分布式状态分片怎样省显存？

| 方案 | 通常分片的状态 | 大致需要的通信 |
| --- | --- | --- |
| 普通 DP | 每卡完整参数、梯度、优化器状态 | 梯度归约 |
| ZeRO-1 | 优化器状态 | 状态相关同步与梯度通信 |
| ZeRO-2 | 再分片梯度 | 梯度归约/分发 |
| ZeRO-3 / FSDP 类方案 | 再分片参数 | 计算前获取必要参数，之后回收 |

具体框架的获取时机、预取和持久化策略不同。状态分片的省内存收益，需要和通信带宽、层大小及重叠效率一起衡量。

## 训练失败怎样排查？

| 现象 | 先核对 | 后续方向 |
| --- | --- | --- |
| 损失异常低但任务很差 | 标签错位、未来信息泄漏、数据污染 | 独立任务评估 |
| 损失不下降 | 梯度是否产生、目标 Mask 是否全空、参数是否更新 | 学习率、数据和初始化 |
| 中途 NaN | 输入异常、全屏蔽注意力行、精度与激活尺度 | 损失缩放、裁剪与高精度算子 |
| 恢复后跳变 | 优化器、调度器、随机状态、数据游标 | 完整检查点恢复 |
| 训练正常但领域表现倒退 | 数据配比、遗忘、过拟合 | 混合数据与领域回归集 |

## 数据并行与状态分片怎样配合

普通数据并行让各副本处理不同数据，再同步梯度，使参数按同一有效批次更新。状态分片把原本每个副本重复持有的参数、梯度或优化状态分散保存，计算时获取需要的部分。

因此分片减少的是重复存储，代价是额外通信与调度。All-gather、reduce-scatter 和参数预取可以与计算重叠，但重叠受层大小、网络、内存余量和依赖约束。节省显存不保证缩短训练时间。

[ZeRO](https://arxiv.org/abs/1910.02054)是这种思路的典型方案。FSDP 类实现的获取、释放和预取策略需要结合实际框架说明，不能把名字当成完整执行计划。

## 张量、流水线、上下文与专家并行

张量并行拆分层内矩阵，流水线并行拆分层阶段，上下文或序列相关并行拆分位置或某些激活计算，专家并行拆分 MoE 专家。它们与数据并行和状态分片可以组合。

流水线要安排微批次流动，阶段工作不均和前后空闲形成气泡；张量并行在层内频繁通信，拓扑时延很重要；长序列并行需要正确处理位置之间的信息与梯度；专家并行则面对动态路由和热点。

并行策略不是越多越好。首先确认是参数、激活、计算还是通信限制，再选择拆分轴。集群规模扩大还要检查有效批次与优化目标是否随之改变。

## 检查点的一致性

可恢复检查点需要同一训练步的权重、优化器、调度器、随机状态、数据游标与分片描述。异步保存时要先形成一致快照，再明确持久提交完成，不能把部分文件写完当作可用版本。

恢复到不同设备数量可能需要重新分片，数据采样顺序与归约数值也可能变化。因此可以恢复可训练状态，不等于必然逐位复现后续轨迹。需要区分语义恢复与严格数值复现。

检查点频率在停顿、存储容量和故障后重做工作之间取舍。只优化保存时间而忽略恢复时间，也会误判整体可用性。

## 稳定性问题与系统问题

数值溢出、梯度异常、数据错误、目标 Mask 错误和同步问题都可能表现为损失跳变。性能下降则可能来自数据供给、通信、慢 worker、重计算或检查点。

观察应关联批次来源、有效 Token、损失、梯度范数、参数尺度、阶段耗时与状态版本。损失曲线提供现象，数据与系统记录提供原因。领域质量仍需要独立任务评估，不能仅由训练稳定推断。
