# 26 · 模型资产、版本与发布生命周期

[知识地图](00-learning-roadmap.md) · [数据生命周期](15-data-lifecycle.md) · [生产评估](22-evaluation-and-production.md)

## 模型资产不止一份权重

一次可复现的模型运行需要结构配置、权重、Tokenizer、消息模板、模态处理器和执行约定。量化模型还需要量化格式与元数据，适配模型需要基础模型与适配器关系。

训练恢复另需优化器、学习率调度器、随机状态、数据游标和分布式状态描述。用于推理的精简导出可以省去这些训练对象，但不能据此声明可以原样恢复训练。

| 资产 | 与什么必须匹配 | 不匹配可能造成什么 |
| --- | --- | --- |
| Tokenizer 与特殊 Token | 词表、Embedding 与训练格式 | 相同文本变成不同输入或边界 |
| 架构配置 | 权重尺寸、位置与注意力结构 | 无法加载或计算语义错误 |
| 聊天模板 | 后训练的消息序列 | 指令遵循和工具调用退化 |
| 量化元数据 | 权重布局与执行内核 | 数值错误、回退或不支持 |
| LoRA 适配器 | 基础版本、目标模块与秩 | 行为错误或加载失败 |
| 模态处理器 | 编码器、分辨率与特征约定 | 视觉/音频输入语义不一致 |

模型名称是人类标识，内容哈希、版本及依赖清单才帮助确定实际资产。仅报告“用某某模型”无法解释不同运行结果。

## 从检查点到服务版本

训练检查点可以经过合并分片、适配器处理、格式转换、量化、验证和打包形成部署资产。每一步都可能改变布局、数值或依赖，不能把“权重相同”理解为所有行为不变。

部署包要说明基于哪个训练版本、做过哪些变换、采用什么模板和默认解码设置。质量验证需要覆盖最终部署格式，因为训练态成绩不自动等于量化后或新内核下的成绩。

模型版本、服务版本与应用版本分别控制不同层：同一模型可换执行引擎，同一服务可换 Prompt 与检索数据。将它们都塞进一个版本字符串，会让错误归因困难。

## 模型选择由任务边界开始

质量、上下文有效使用、结构化输出、工具行为、多语言、多模态和部署成本是不同能力。公开基准可以提供参考，但选择仍要依据目标任务的证据。

参数量不是唯一尺度。稠密与 MoE 的总参数和激活量不同；更小但针对任务适配的模型可能更有效；更强的模型也可能有较高延迟。服务容量还受缓存和输出长度影响。

可选路径包括托管 API、自托管开源权重、专用小模型及混合路由。它们对资产控制、运维、资源与接口兼容有不同要求，不应把一个选型结论套在所有组织上。

## Prompt 也是版本化行为配置

系统指令、少样本示例、工具描述、输出 Schema 和证据组织会影响行为。它们需要与模型、数据和任务版本关联，而不是线上随手改一段文本却不留记录。

Prompt 缩短可能减少 Token 和 Prefill，也可能删除关键条件。增加示例可能改善格式，却挤占证据预算。行为配置的改变要与质量和性能一起理解。

工具 Schema 改名或字段单位变化，可能破坏已有示例与后训练约定。适配器切换同样影响 Prefix Cache 是否有效，需要把缓存与行为版本联系起来。

## 多模型路由与级联

路由可以按任务类型、模态、长度、质量要求或实时负载选择模型。级联则先尝试低成本路径，在验证不足时升级。前提是有可信的分流信号与结果判断。

模型自报置信度通常不足以决定是否升级。可用信号包括任务难度类别、证据完整性、规则验证和执行测试。路由器错误也会影响总质量，因此要评估路由后的端到端结果。

升级并非免费：第一次调用的成本、额外等待与重复读取都会计入任务账。把失败小模型的成本忽略后只比较第二个模型价格，会低估真实成本。

## 发布与回退依赖兼容性

新版本先完成离线评估和容量判断，再通过影子流量或小范围放量观察。影子调用若涉及写工具必须有合适隔离，不能把测试流量当作真实动作执行。

回退不仅是切换模型名：消息历史、持久任务状态、工具协议和索引版本要兼容。KV Cache 通常无法跨不同权重直接继承，旧请求是继续完成、迁移还是取消，需要明确语义。

数据与模型双重升级会使差异归因困难。可分别比较或记录完整组合版本，保留已知可用的组合。发布管理针对的是系统配置集合，而不是单个二进制文件。

## 模型漂移与持续更新

模型权重固定时，数据、用户任务、工具和检索资料仍可变化，最终行为因此变化。线上质量下降不能仅凭“模型版本未变”排除系统变化。

持续训练要处理新旧数据配比、遗忘和反馈偏差。线上生成内容进入下一轮训练之前需要质量审核；直接把所有回复再训练可能强化模型原有错误。

有时无需改权重：制度更新用索引更新，接口变化用工具兼容，格式问题用 Prompt 或 Schema。不同变化应在对应层解决，降低不必要的训练与部署复杂度。

## 成本与可维护性

总成本包括模型调用或设备、检索与工具、数据处理、存储、失败重试、人工修订和运维。每成功任务成本比单次请求价格更接近产品结果，但需要一致的成功标准。

自托管需要考虑空闲容量、峰值、副本冗余、冷启动与升级；托管 API 需要考虑接口变化、额度和服务行为。容量与质量之间存在取舍，版本管理让这些取舍可追溯。

## 可复现记录

一次结果至少应关联模型与资产标识、模板和 Prompt 版本、检索快照、工具协议、引擎与精度、解码参数、输入来源及时间。生成随机性与浮点执行会影响严格复现，记录能解释差异，不代表保证逐字相同。
