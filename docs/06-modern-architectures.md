# 06 · 现代大模型的架构变体

[返回目录](../README.md) · [下一章](07-pretraining.md)

## 用问题理解变体

很多缩写都是在改善基础 Transformer 的一个瓶颈。先问它改了哪一部分，再问成本和效果。

| 技术 | 改动位置 | 主要目的 | 代价或边界 |
| --- | --- | --- | --- |
| Pre-Norm / RMSNorm | 子层前后的归一化 | 训练与数值稳定性、实现效率 | 与整体参数化和训练配置配合 |
| SwiGLU | FFN 激活与门控 | 改善特征变换能力 | 比较成本时要考虑中间维度与投影数 |
| RoPE | Attention 的 Q/K | 将相对位置信息融入点积 | 长度外推不自动可靠 |
| MQA / GQA | Q 头与 K/V 头对应关系 | 减少 KV Cache 与读带宽 | 共享程度影响容量，需训练适配 |
| MoE | 常见为 FFN 替换成专家与路由 | 扩大总容量，控制每 Token 激活计算 | 路由、负载均衡、通信与存储更复杂 |
| 滑窗 / 稀疏注意力 | 可访问的位置 | 降低长序列计算与缓存负担 | 信息路径与远距离能力发生变化 |
| SSM / 混合架构 | 序列信息传播机制 | 提供另一种状态更新与长序列设计 | 精确检索、训练与硬件效率需实测 |

## RoPE：位置通过旋转进入点积

RoPE 对 Q/K 的成对维度施加随位置变化的旋转。这样它们的点积能够带上相对位置的影响。一般不直接旋转 V。

增加配置里的最大长度，不能保证模型在更长序列上正常工作。还需要考虑位置缩放方法、长序列训练或适配、任务评估，以及缓存与算力。

## SwiGLU：内容乘以门控

一种常见写法是：

```math
\mathrm{SwiGLU}(x)=\left(\mathrm{SiLU}(xW_g)\odot xW_u\right)W_d
```


$`\odot`$ 为逐元素乘法。一个投影产生内容，另一个通过激活产生门控，最后投影回隐藏维度。这里省略偏置，实际实现可能不同。

门控 FFN 有三组主要矩阵，不能与两矩阵 FFN 在相同中间维度下直接宣称成本一致。

## MHA、MQA、GQA

| 形式 | 查询头 | K/V 头 | 共享方式 |
| --- | --- | --- | --- |
| MHA | `h_q` | `h_q` | 每个查询头有对应 K/V 头 |
| MQA | `h_q` | 1 | 所有查询头共享一组 K/V |
| GQA | `h_q` | `h_kv`，通常介于两者之间 | 每组查询头共享 K/V |

KV Cache 容量主要随 $`h_{kv}`$ 变化，不是随 $`h_q`$ 单独变化。GQA 不会使注意力读取历史信息这件事消失；只是减少缓存与相关带宽需求。

## MoE：总参数与激活参数

常见稀疏 MoE 为每个 Token 选取少数 FFN 专家：

```math
y=\sum_{i\in\mathrm{TopK}(g(x))}\alpha_i\,E_i(x)
```


路由器 $`g`$ 选专家，$`\alpha_i`$ 是混合权重，$`E_i`$ 是专家网络。有的实现包含始终激活的共享专家。

- 总参数包含所有专家及共享部分，决定权重存储规模。
- 激活参数只计当前 Token 实际使用的部分，更接近其计算开销，但不能单独决定延迟。
- 需要处理专家负载不均、跨设备传输和路由效率。
- 专家通常通过训练形成分工，不是人工指定的「法律专家」「医疗专家」。

「只有少量参数激活」不代表未激活专家无须存储。卸载方案可能减小显存占用，却引入搬运和调度成本。

## FlashAttention 属于什么？

FlashAttention 主要改变注意力的执行算法与显存访问方式，使用分块等方式避免保存完整注意力矩阵；它通常保持标准注意力的数学语义，数值结果可能有浮点差异。

它不是稀疏注意力，也不会把普通全注意力的算术复杂度直接变成关于序列长度的线性。

## SSM 与混合模型

状态空间模型用状态更新传播序列信息。Mamba 等选择性 SSM 提供了 Transformer 之外的设计路线；混合模型可把状态模块与注意力交替组合。

不同模块分别影响训练并行、推理状态量、信息保留和硬件效率。不能仅凭「线性复杂度」断定某个模型在所有任务、长度和设备上都更好。

## 变体作用于不同瓶颈

位置机制处理顺序与距离，头共享处理 KV 状态，专家结构处理容量与激活计算，局部注意力处理可访问范围，执行内核处理数据搬运。它们可以组合，因此比较模型时要看整个配置，而不是某个缩写。

一个使用 GQA 的模型可以同时使用 RoPE、SwiGLU、MoE 与高效注意力。量化又是独立的数值与执行维度。某项优化降低一种资源，另一项可能增加通信或工作区，总体效果需要沿完整请求看。

## RoPE 与长上下文适配

RoPE 利用位置相关的旋转改变 Q/K 的点积关系，为注意力提供相对位置信息。它并非把位置当成普通词向量加到输入，也不等于因果 Mask。

不同频率与长度缩放改变模型看到的位置关系。推到训练范围外时，表示变化和任务分布都可能造成退化；长上下文适配还需要训练与针对不同位置的评估。

历史 K 的位置处理与新查询必须一致。服务端简单修改最大长度，而不处理模型与缓存语义，可能得到能接收输入但不能可靠使用的信息窗口。原始依据：[RoFormer](https://arxiv.org/abs/2104.09864)。

## GQA 的收益与保留的工作

多个 Query 头共享较少 K/V 头，使缓存和相关投影缩小；Query 仍形成多个信息选择关系，历史仍需要被读取。高效实现按分组访问 K/V，若实际复制多份缓存，会损失应有收益。

共享程度影响表示容量与训练适配，不能直接把既有 MHA 权重切掉头就假设质量不变。具体收益受序列长度、批次、算子与架构共同影响。[GQA 论文](https://arxiv.org/abs/2305.13245)讨论了从多头检查点进行适配的方法。

## MoE 的路由就是数据路径

路由器为每个 Token 选择少量专家，先发送表示，再执行专家，再汇总结果。一个批次不同 Token 可以覆盖许多专家，所以激活参数小不代表整个批次只访问少量权重。

专家分布在多设备时，路由产生 all-to-all 类通信。热门专家可能成为瓶颈，容量限制、均衡目标和共享专家等设计缓解不同问题。具体方案是否丢弃、改派或等待 Token，需要按实现判断。

专家不是人工命名的学科模块，路由不等于对“法律问题”调用一个固定法律服务。它仍然是模型内部学习到的计算选择。原始入口：[Switch Transformers](https://arxiv.org/abs/2101.03961)。

## 稀疏访问与状态压缩的不同取舍

窗口注意力减少直接读取的历史范围，稀疏连接保留某些远距离通道，SSM 将历史压进更新状态，混合模型组合这些机制。它们改变信息保留与访问方式，而不是仅改变矩阵存储。

固定或较小状态有利于生成容量，却需要在状态里保留未来可能需要的信息；全注意力保留可回读的历史，资源随上下文增长。精确检索、长程关联和任务质量因而是与复杂度同样重要的比较维度。

某些架构还压缩或改变缓存表示，不能继续套标准 K/V 头的容量关系。公开模型配置与官方实现是判断实际结构的依据，不推测未公开系统。
