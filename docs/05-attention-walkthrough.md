# 05 · 注意力的信息流与上下文机制

[知识地图](00-learning-roadmap.md) · [Transformer](04-transformer.md) · [架构变体](06-modern-architectures.md)

## 注意力解决的是信息选择与组合

序列模型需要在不同位置之间传递信息。固定长度的局部窗口难以直接连接相距很远的内容；把整个序列压进单个固定状态，又要求有限状态保留后续所有可能需要的信息。注意力让每个查询位置按当前表示，动态选择其他位置的信息。

这不是从原文中找一句话复制到输出。每层传递的是经过投影的向量特征，后续还会经过输出投影、残差与非线性变换。因此注意力既可以参与指代和条件关联，也可以组合跨位置的抽象特征，不能只理解成关键词匹配。

## 匹配特征与传递内容为什么分开

Query 描述当前位置需要匹配的特征，Key 描述各位置可被匹配的特征，Value 描述匹配后传递的内容。三者是共享权重对隐藏状态的不同投影，没有预先指定的人类语义。

把 Key 与 Value 分开，使“按什么找到信息”和“找到以后传什么”可以分别学习。一个位置可以凭某种关系被选中，却传递另一种特征。输出仍是允许位置的 Value 的加权组合；单个头不能任意创造不在其值空间中的内容，整个网络通过投影、多个头和 FFN 增加表达能力。

注意力权重按每个查询归一化，不是整段文本只有一份统一的重要性排名。同一个键对不同查询可以有不同权重，同一个位置在不同层也可以承担不同作用。

## 自注意力与交叉注意力

| 形式 | Query 来自哪里 | Key / Value 来自哪里 | 典型关系 |
| --- | --- | --- | --- |
| Self-Attention | 当前序列 | 同一序列 | 文本位置之间的信息组合 |
| Cross-Attention | 目标序列或查询表示 | 另一组表示 | 解码器读取编码器输出、文本读取视觉特征 |
| Causal Self-Attention | 当前序列 | 被因果约束的当前序列 | 自回归生成只依赖已知前缀 |

原始 Encoder–Decoder Transformer 在 Decoder 中同时使用因果自注意力和对 Encoder 输出的交叉注意力。Decoder-only 通常把指令与内容放到同一序列，通过因果自注意力建立联系。两者可以实现相近任务，但数据路径、Mask 和缓存对象不同。

## Mask 决定计算图中允许存在的关系

因果 Mask 屏蔽未来位置；Padding Mask 屏蔽用于对齐的空位置；文档边界 Mask 可以阻止打包后的独立样本互相读取；局部或块稀疏 Mask 定义其他访问结构。

这些关系先作用于分数，再在允许位置上归一化。先汇总所有位置再删去未来内容，已经无法撤销泄漏。Loss Mask 只决定哪些目标参与损失，无法阻止模型读到未来答案。

每个有效查询必须有合理的可访问键。全屏蔽行、错误的 Padding 方向和不匹配的位置偏移，都可能造成非有限值或看似正常的错误输出。Mask 因此属于模型语义，而不是可随意更换的性能开关。

## 一层连接远处，多层组合关系

全注意力可以在一层中直接读取远处位置，但一次读取并不等于完成复杂推理。模型仍需要识别适用条件、组合多个片段、处理冲突，并把这些关系转成输出。

多层网络让后一层读取已被前一层更新的表示，形成层级信息组合。局部注意力则通过多层传播或额外全局连接建立远距离路径。滑窗层的窗口小，不必然意味着整网完全无法使用远处信息，但改变了路径长度、容量和精确回读能力。

位置机制还参与匹配。因果 Mask 提供方向约束，却不能完整表达两处相隔多远。RoPE 等方法让位置进入 Q/K 关系，与访问边界共同决定上下文计算。

## 注意力权重与模型解释的边界

高权重表示某个头在这次汇总中更偏向某个 Value，不证明那段原文就是最终答案的唯一原因。Value 的内容、其他头、输出投影、残差、FFN 与后续层都会改变影响。

观察权重适合检查信息流线索；对因果影响的判断通常还需要干预、消融或其他分析。不能把一张漂亮的热力图直接作为完整的可解释性证明，更不能把模型显示的推理文本等同于全部内部机制。

## 长上下文的三种不同限制

第一是容量：模型与服务能接受多长输入。第二是执行代价：全注意力需要处理大量位置关系，Decode 还要不断访问增长的历史。第三是有效使用：模型能否在远距离、干扰内容和复杂条件下找到正确事实。

扩大上下文配置只触及第一项的一部分。位置适配、训练分布、证据组织和评估共同影响第三项。长上下文可降低部分检索需求，但不能替代资料更新、访问控制和可追溯引用。

## 架构与执行优化的分界

稀疏注意力改变允许的信息关系；GQA 改变查询与 K/V 的共享结构；FlashAttention 主要改变标准注意力怎样分块执行与访问显存。它们处于不同设计维度。

高效内核可以避免把完整分数矩阵写入显存，但标准全注意力仍要处理对应的查询与键关系。执行更省内存，不意味着自动获得线性的全注意力算术复杂度，也不意味着模型更擅长长文理解。
