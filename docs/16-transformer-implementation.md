# 16 · 模型计算布局、算子与执行语义

[返回目录](../README.md) · [模型计算](04-transformer.md) · [训练系统](17-training-engineering.md)

## 从数学张量到内存中的数据

模型定义规定允许关系与算术，实现决定元素怎么排、怎样分块和何时读写。相同形状不保证元素对应正确，同一数学表达也不要求同一个内核。

参数是跨请求复用的权重；激活是当前前向的表示；KV 是按请求和层保存的历史状态；训练还需梯度与优化器历史。生命周期不同，不能统一当成“模型内存”。

## 拆头不仅是改形状

普通 MHA 投影结果可先表示为 `[B,T,h,d_h]`，再交换 Token 和头轴成为 `[B,h,T,d_h]`。reshape 重新解释维度分组，transpose 改变轴映射；不交换轴就直接 reshape 成后一形状会把位置与头混在一起。

转置视图可能没有复制数据，但产生不同 stride；后续内核能否直接处理取决于布局支持。要求连续布局时的实际复制产生带宽和临时内存成本。拼头要执行正确的逆映射，不只是元素总数相同。

GQA 还需将每个 Q 头对应到正确 K/V 组。逻辑广播共享 K/V 不要求把物理缓存重复存为 Q 头数；展开复制会增加实际读写和容量。

## 打包变长序列要保留边界

多个请求可将有效 Token 打包为 `[sum(T_i),d]`，省掉 padding。引擎另外提供序列起止偏移、Q/K 长度、全局位置与块表。Attention 必须区分序列，不能把打包数组当成一条长文本。

Cached Attention 的 Query 长度与 Key 长度通常不同。多个新查询的因果限制要与历史位置对齐；不能把方阵下三角模板随意截成矩形，否则可能屏蔽应读历史或放开未来候选。Mask 的语义由全局位置决定。

## 投影与融合改变了哪些读写

Q/K/V 投影常可合成一次矩阵乘，再按宽度切出结果；各段仍代表独立权重，GQA 的 Q 段与 K/V 段可能不同宽。融合可将 bias、位置变换或缓存写入接在投影后，减少中间张量落到 HBM。

融合逐元素算子省内核启动和多次读写，但范围过大可能增加寄存器需求、降低并发或限制动态形状。它不是把 Norm、残差或门控删除。权重布局也要匹配内核，格式转换有启动与运行成本。

## FlashAttention 为什么不需要完整分数矩阵

朴素实现把 QK 分数写到 HBM，再读回做 Softmax，保存权重供与 V 相乘。长序列中间矩阵很大。分块实现将小块 Q/K/V 放进片上资源，计算局部分数并立即汇总，而不保存完整矩阵。

难点是 Softmax 分母取决于一行所有键，不能每块独立归一化再直接平均。便于理解的在线状态是每个查询保存：

| 状态 | 含义 | 新键块到达时怎样合并 |
| --- | --- | --- |
| `m` | 已见分数的最大值 | 更新为旧块与新块最大值的较大者 |
| `s` | 相对 m 指数化的权重总和 | 最大值变化时先将旧总和按新基准缩放，再加新块 |
| `u` | 同样基准下的未归一化加权 V 总和 | 以同一比例缩放旧累积，再加新块的加权内容 |

所有允许块处理完后取 `u / s`。保持同一归一化基准，使组合仍对应整行 Softmax；实现也可保存归一化输出或等价统计量。Mask 在局部分数中处理，因果块可跳过不允许区域。

反向可保存必要输出与归一化统计，再在块内重算分数/概率，减少巨大的保存状态。重计算增加部分算术，却可能因减少 HBM 访问而更快。算法保持标准注意力语义，浮点求和顺序可能不同；它不是稀疏注意力，全注意力算术量仍随长度平方增长。依据：[FlashAttention](https://arxiv.org/abs/2205.14135)。

## 增量执行必须保持什么一致

位置、权重/适配器、层编号、头对应与缓存精度要对齐。RoPE 常在写 K 前完成位置处理，再读取不能重复旋转。历史长度与分配长度也要区分，未初始化但已分配的槽位不能参与 Attention。

数学相同也会因末端位置选错、padding 或缓存偏移错误而输出不同。机制验证要比较完整前向与缓存前向，检查改变未来 Token 不影响旧位置，覆盖分块、分叉和变长批次。正常浮点差异应与结构性错误分开。

物理分块、共享与在途访问见[第 18 章](18-inference-engineering.md)；此处关注算子对元数据的解释。

## 精度沿整条计算链传播

权重、输入乘法、累加、Norm/Softmax 归约与最终输出可采用不同精度。低精度输入不等于所有累加都低精度；长归约、极端 logits 和重复生成可能放大误差。

比较实现时固定 Mask、位置、模型模式与输入；训练态 dropout 和推理态行为不同。只比较几个输出 Token，可能漏掉尚未改变采样的数值偏差；只追求逐位相同，又可能误拒绝等价浮点实现。

## 图执行与动态请求怎样共存

CPU 每轮构造并启动多个内核可能成为小批次瓶颈。编译和图重放可减少部分调度开销，但常要求可预测的形状、地址或缓冲约定。引擎可准备若干形状档位并填充元数据，对不匹配工作回退到其他路径。

填充增加工作，图缓冲占用内存，地址需要在重放期间有效。分页地址变化不能靠改一段主机列表自动生效，必须在图使用的设备元数据中正确发布。通信、CPU 后处理与变长输出不会因使用图就全部消失。

## 存储分片不等于计算分片

检查点拆成多个文件是加载格式；TP 按矩阵语义切权重并交换结果是执行方案。加载器要映射参数名、方向、切片与量化布局，不能按文件数量推断 TP 卡数。

矩阵切分见[第 10 章](10-serving-and-distributed.md)，训练状态分片见[第 17 章](17-training-engineering.md)。实现入口：[PyTorch](https://docs.pytorch.org/docs/stable/index.html)；接口与内核支持以实际版本为准。
