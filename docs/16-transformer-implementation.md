# 16 · 模型计算布局、算子与执行语义

[知识地图](00-learning-roadmap.md) · [Transformer 结构](04-transformer.md) · [计算基础设施](27-compute-infrastructure.md)

## 同一个模型有三种描述层次

模型结构描述有哪些参数与运算；张量布局描述数据在批次、序列、头和特征维度上如何组织；执行计划描述哪些运算融合、何时搬数据、在哪里通信。这三层共同决定一个模型怎样落到硬件上。

数学上相同的运算可以采用不同布局和内核。相反，形状相同的程序也可能因为轴、Mask 或位置语义不同而实现了另一个模型。理解执行首先要知道被保留的语义，再判断性能优化改变了什么。

## 参数、激活与请求状态

| 对象 | 生命周期 | 是否跨请求共享 | 主要用途 |
| --- | --- | --- | --- |
| 权重 | 模型版本生命周期 | 通常只读共享 | 定义计算规则 |
| 中间激活 | 一次计算及训练反向所需范围 | 通常不直接共享 | 表示与运算中间结果 |
| KV Cache | 请求或可复用前缀生命周期 | 符合条件时可共享 | 保存历史位置每层 K/V |
| 优化器状态 | 训练任务生命周期 | 按训练并行策略组织 | 决定参数更新 |
| 运行时工作区 | 算子或进程生命周期 | 由引擎管理 | 临时缓冲、执行图与通信 |

权重文件不包含当前用户的聊天进度。KV Cache 也不是参数的增量版本。这些对象混淆后，缓存回收、模型热更新和故障恢复都会发生错误。

## 逻辑维度与物理布局

隐藏状态常用 `[B,T,d]` 表示批次、位置和特征。多头注意力把特征拆成头与每头维度，再让各头独立计算。reshape 表达拆分，transpose 或布局变换表达轴的交换；它们并非同一操作。

一个张量可能逻辑上连续，却在某个轴上跨步访问。转置有时只改变视图，不搬数据；后续算子需要连续内存时才发生实际复制。融合算子可能直接接受另一种布局，从而省去中间转置与写回。

生产引擎还会把不等长序列压成连续的有效 Token 区间，并用长度或偏移描述样本边界。这样减少 Padding 运算，但边界和位置必须准确，不能让不同请求互相注意。

## 线性投影与算子融合

Q/K/V 逻辑上是不同投影，实际可将权重拼接后一次矩阵乘法得到，再拆分输出。门控 FFN 的部分投影、偏置、激活和逐元素乘法也可以融合。

融合的收益来自减少内核启动、临时张量和显存往返，而不一定减少模型定义所需的乘加次数。更大的融合内核也可能增加寄存器压力、降低某些形状的利用率，所以效果与输入长度、批次和设备相关。

LM Head 将隐藏状态映射到词表分数。训练可能需要大量位置的损失，生成通常只需末端位置；是否显式保留全部 logits 会显著影响工作区。输出层不能仅因为“最后只选一个 Token”就被省略。

## 高效注意力怎样保持语义

朴素注意力先生成完整分数矩阵，再做 Softmax，再乘 Value。高效实现分块读取 Q/K/V，并维护归一化统计，逐步累积输出，减少大中间矩阵的显存读写。

保持语义的关键是每个查询仍对所有允许键使用同一个归一化结果，而不是把每块分别归一化再简单相加。浮点运算顺序改变可以产生小差异；因果边界、缩放和允许关系改变则是模型语义变化。

FlashAttention 属于这一执行维度。稀疏化、窗口化和结构性缓存压缩则可能改变模型计算或可访问状态，需要单独评估。[原论文](https://arxiv.org/abs/2205.14135)讨论的是 IO-aware 的精确注意力执行。

## 增量执行中的位置与缓存

完整 Prefill 时查询和键都覆盖输入序列；续写时查询覆盖新增位置，键和值包含历史与新增位置。缓存必须按层保存，因为各层表示不同。

一次续写多个 Token 时，每个新查询能读全部合法历史及本次此前的位置，不能直接套用没有历史偏移的普通三角 Mask。位置编号也必须继续，RoPE 的新 Q/K 要与历史 K 使用一致的位置规则。

缓存复用依赖相同前缀、权重、适配器、位置和访问语义。旧前缀被编辑后，受影响位置及其后续计算通常需要重建。缓存格式、量化和不同内核可以引入数值差异，但不能因此忽略内容和边界错误。

## 数值精度影响的是一条计算链

权重存储精度、乘法精度、累加精度和输出精度可以不同。低精度减小字节量并可能提高吞吐，但也会改变舍入误差和动态范围。

Softmax、归一化、极值处理和长序列归约对数值行为敏感。仅检查最后没有 NaN 不足以判断正确；应保持合理的参考语义并关注任务质量。训练态的 Dropout 与推理态的确定性设置也属于计算模式的一部分。

## 编译、动态图与执行图

图编译可以做算子融合、消除冗余、规划内存和选择内核；执行图重放可以减少重复启动开销。动态请求长度与批次会使形状集合变化，产生重新编译、Padding 或额外图版本。

图本身也占内存。为了覆盖很多批次形状而捕获大量图，可能压缩可用于 KV 的容量。编译时固定的地址、形状和控制流限制，需要与连续批处理的动态性配合。

## 权重分片与计算分片是不同格式

把一个权重文件拆成多个文件，解决存储与加载规模；把一个矩阵分到多个设备计算，才是张量并行。磁盘上的 shard 不能直接推断运行时 TP 拓扑。

模型加载要把存储命名、张量布局、量化元数据与架构配置对齐；有些格式还需要转换。服务启动慢可能来自下载、反序列化、格式转换、设备搬运或编译，应分别观察。
