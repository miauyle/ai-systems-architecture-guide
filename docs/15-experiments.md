## 实验 1：复算 Attention

**依赖：**Python 3 标准库即可，不需要 GPU。

把 05 的代码保存为临时 `attention_demo.py`，运行 `python attention_demo.py`。

| 改动 | 先预测 | 再观察 |
| --- | --- | --- |
| Q 改为 `[0,1]` | 哪些键更匹配？ | 权重如何变化 |
| 所有 K 改成相同值 | 是否均匀分配？ | V 的平均值 |
| 仅修改 V | 权重是否变化？ | 输出是否变化 |
| 将一个位置 Mask 掉 | 剩余权重如何变化？ | 是否重新归一化 |

**验收：**能解释「匹配」与「汇总」为什么是两个计算步骤。

## 实验 2：显存估算器

```python
def weight_gib(params, bytes_per_parameter):
    return params * bytes_per_parameter / 2**30

def kv_gib(batch, length, layers, kv_heads, head_dim, bytes_per_value):
    return (2 * batch * length * layers * kv_heads * head_dim
            * bytes_per_value / 2**30)

print('7B BF16 weight GiB:', weight_gib(7_000_000_000, 2))
print('MHA cache GiB:', kv_gib(1, 4096, 32, 32, 128, 2))
print('GQA cache GiB:', kv_gib(1, 4096, 32, 8, 128, 2))
print('8 requests GQA GiB:', kv_gib(8, 4096, 32, 8, 128, 2))
```

预期约为 `13.04`、`2.0`、`0.5`、`4.0`。该实验只计算理想权重和标准 KV，不估算全部运行显存。

**验收：**把长度翻倍、K/V 头数减半、并发翻倍，能先预测结果，再计算验证。

## 实验 3：观察 Tokenizer

**依赖：**任选你可以使用的目标模型 Tokenizer 或其官方在线工具。需要本地库时参考[官方工具资料](references.md)，使用与模型一致的版本。

对比中文、英文、代码、日期和生僻字符。记录原文本、字符数、Token 数和实际切分结果。

**验收：**能说明为什么不能用固定的「每字多少 Token」估算所有输入；了解特殊 Token 和聊天模板也占用预算。

## 实验 4：做一个不依赖模型的检索评估

准备 10–20 个公开或自建的小文档和若干问题，人工标记每题应该检到哪一段。先采用最简单的关键词检索，再尝试语义检索或二者融合。

比较 top-k 中是否含正确证据，记录错误原因：词不匹配、文档分块不完整、版本错误或真正没有答案。

**验收：**在接入生成模型之前，能独立评价证据是否被找回。

## 实验 5：Prompt 与 RAG 的对照

**依赖：**你已有权限使用的模型 API 或本地模型。调用可能产生费用，先设置自己的预算；只使用允许提供给该模型的数据。

使用同一模型和相同解码设置比较：普通提问、加入格式规则、加入相关证据、加入无关证据。逐项记录结论正确性、引用、缺失信息处理、延迟和 Token 用量。

**验收：**能区分行为改善与知识补充；能发现错误证据也可能导致错误回答。

## 实验 6：定位延迟

对相同任务分别使用短/长输入和短/长输出，记录 TTFT、端到端时间及服务给出的用量。具备服务指标时进一步分离排队、prefill、decode 和检索时间。

**验收：**不把一次请求慢的原因全部归到「模型大」；报告结果时明确负载、并发和计时范围。

## 进一步的完整实现实验

基础实验完成后按[连续课程](../course/README.md)运行[五个教学示例](../examples/README.md)：

- Transformer：完整计算、逐 Token 缓存、分块续写和未来泄漏检查。
- 训练：显式交叉熵梯度、有限差分和重复索引累加。
- 上下文注意力：训练 Q/K/V，检查未见前缀、输入干预及最后 Token 模型的信息上限。
- 检索：组织/版本过滤，手算与运行 BM25，核验原文证据。
- Agent：写成功但回执丢失、对账、重复调用与权限拒绝。

课程 02–07 按学习顺序解释这些程序，16、17、19、20 专题进一步展开。先预测哪个性质应保持，再修改一个变量；不要把随机模型的输出当成语义能力证据。
