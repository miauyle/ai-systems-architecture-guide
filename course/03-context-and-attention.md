# 第 3 课：让末尾读到开头，训练一个注意力模型

[课程目录](README.md) · [上一课](02-tensors-and-gradients.md) · [下一课：完整 Decoder](04-decoder-and-training.md)

前两课已经能计算概率、损失和梯度，但只看 `问` 的模型仍不知道需要回答哪一个符号。本课解决信息传递：怎样把序列中有用的位置汇总成最后一个位置的表示，并把汇总规则学出来。

## 1. 为什么不用把整段输入直接拼起来

一个可行方案是把五个位置的向量拼成一个长向量，再经过神经网络。这种模型也能学会我们的固定长度任务。注意力并不是唯一能解决它的方法。

但如果位置数从 5 变成 500，拼接层的输入尺寸跟着变；它也没有直接表达“根据当前问题，从多个位置读取信息”的计算结构。另一种方案是循环地维护隐藏状态；它固定状态尺寸，但长距离信息必须经过多次状态更新。

注意力选择一个更直接的结构：每个位置产生可被读取的内容和匹配特征；当前位置产生查询；对可见的位置计算匹配程度，并按匹配程度汇总内容。长度变化时，主要变化的是被读取的集合，而非线性投影矩阵的形状。

## 2. 从“带权平均”逐步推出 Q、K、V

先假设三个位置包含内容向量：

```text
V1=[10,0]，V2=[0,10]，V3=[5,5]
```

如果权重为 `[0.4,0.2,0.4]`，输出是：

```text
0.4×[10,0]+0.2×[0,10]+0.4×[5,5]=[6,4]
```

问题变成：谁来决定权重？设当前查询 `q=[1,0]`，三个位置的匹配向量分别为 `k1=[1,0]`、`k2=[0,1]`、`k3=[1,1]`。点积评分是 `[1,0,1]`。

把评分除以维度平方根，再过 softmax，得到 `[0.401112,0.197776,0.401112]`，加权输出约 `[6.01668,3.98332]`。整个过程可微，因此能够沿第二课的链式法则学习。

查询、匹配特征、内容分别称为 Query、Key、Value。它们不是写死的业务字段，而是从输入表示经不同矩阵投影产生的向量：

```math
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
```

```math
A=\mathrm{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}+M\right),\qquad Z=AV
```

每一行 softmax 沿 Key 位置归一化。M 是可见性掩码：允许读取的位置加 0，禁止的位置在理想数学表达中加负无穷。工程实现需选择数值稳定的掩码与算子，尤其避免整行都被屏蔽。

为什么不直接把 X 同时当成 Q、K、V？那也能计算一种注意力，但会强迫“怎样匹配”和“要传什么内容”使用相同表示。独立投影让二者可以各自学习。

除以平方根的动机是控制点积分数的尺度：在各分量近似独立、方差相近的假设下，点积方差随维度增大。softmax 过早饱和可能使梯度难以有效传播。这个解释是一种初始化尺度分析，不保证训练后分量始终独立。

## 3. 因果掩码与位置信息解决不同问题

若预测第三个输入位置之后的 Token，该位置可以读取第一、二、三个输入位置，不能读取第四个输入位置。三个位置的允许关系如下：

```text
       Key1 Key2 Key3
Query1   ✓    ×    ×
Query2   ✓    ✓    ×
Query3   ✓    ✓    ✓
```

因果掩码避免未来信息泄漏。位置信息则说明 Token 位于哪里。没有位置信息的注意力，对被读取内容的排列有特殊的置换性质，很难区分同一组 Token 的不同顺序。

教学模型使用 `X=E[ids]+P`：E 是 Token Embedding，P 是位置 Embedding。完整现代模型也常用 RoPE 等方案；不能把简单的可学习绝对位置表当作所有模型的共同配置。

在我们的任务中只计算最后一个 Query。它的全部输入都属于历史，所以它可读取五个输入位置，无需构造完整的三角掩码；这并不是取消了因果约束。若把模型用于中间位置，必须同时限制可见范围。

## 4. 对照代码追踪完整前向

运行 [context_attention_train.py](../examples/context_attention_train.py)：

```bash
python examples/context_attention_train.py
```

教学配置：训练 batch 共 192 个样本，序列长 5，词表 9，宽度 16，单头注意力，只监督最后一个位置。前向形状依次为：

| 对象 | 形状 | 意义 |
| --- | --- | --- |
| ids | `[192,5]` | 输入符号编号 |
| E、P | `[9,16]`、`[5,16]` | Token 表与位置表 |
| X | `[192,5,16]` | 各位置的输入表示 |
| q | `[192,16]` | 只取末尾 Query |
| K、V | `[192,5,16]` | 全部历史位置的匹配与内容 |
| scores、A | `[192,5]` | 每个样本对五个位置的评分与权重 |
| Z | `[192,16]` | 汇总后的末尾表示 |
| logits | `[192,9]` | 下一符号的评分 |

参数数目为 `9×16+5×16+3×16×16+16×9=1,136`。位置表和 Embedding 都参与训练，没有使用预训练权重。

这些参数是跨样本共享的。模型不是给 192 个训练样本分别保存一个答案槽位，而是学习一组共同计算规则；是否推广到新组合仍由测试检查。

## 5. 把梯度穿过注意力

第二课已经给出输出 logits 的梯度。接下来用同一个规则传回注意力：

1. `logits=ZWo`，得到 Wo 梯度和 Z 梯度。
2. `Z=Σ AiVi`，Value 梯度为 `Ai×上游梯度`；权重梯度是上游梯度与 Vi 的点积。
3. 权重由 softmax 产生，需要让五个权重的竞争关系一起参与反向。
4. 评分由 q、K 的点积产生，再传回 Wq、Wk、Wv 和 X。
5. 把各位置 X 的梯度累计到 Token 表 E 与位置表 P。

对一个样本，如果权重 A 的上游梯度为 g，则 softmax 评分 s 的梯度为：

```math
\frac{\partial L}{\partial s_i}=A_i\left(g_i-\sum_j A_jg_j\right)
```

减去加权平均使各位置的梯度相互关联。若某个位置读取的内容能够降低损失，其匹配评分就可能被推高；其他位置相对被压低。

代码里的 `ds` 正是这个表达式。模型既可以学“读哪个位置”，也可以学“把那个位置的内容编码成什么”。不能把降低损失仅归因于注意力权重变化。

## 6. 实验结果与它实际支持的结论

在 Python 3.12.14 / NumPy 2.3.5、固定种子、float64、全量 batch、Adam 学习率 `0.02`、350 步的本次运行中：

| 检查 | 结果 |
| --- | --- |
| 六组参数各抽 6 个坐标的中心差分 | 最大绝对误差约 `3.66e-11` |
| 第一次更新前训练损失 | `2.164911` |
| 第 50 次更新前训练损失 | 约 `0.000005` |
| 64 个未训练前缀上的准确率 | `1.000000` |
| 64 个测试前缀的平均损失 | 约 `0.000002` |
| 将开头目标替换为下一个符号后，预测改变的比例 | `1.000000` |

损失是自然对数单位；这不是性能基准。不同浮点库或平台可能产生微小数值差异，关键是梯度一致、未见前缀可预测以及输入干预能改变结果。

查看注意力权重可以发现平均权重几乎全部落在第一个位置。但“注意力集中在那里”本身不证明模型的预测因果依赖那个位置；所以程序还改变第一个 Token，检查预测是否随之改变。

模型只学了固定五位置、四目标的人工规则。测试输入是新干扰组合，规则和长度没有变。想声称更强的泛化，需要额外测试新长度、新位置、新符号，以及干扰包含目标符号等情况；当前位置表甚至不支持超过五个位置。

## 7. 练习与解析

**练习 1。** 把所有权重固定为 `1/5`，模型一定无法完成任务吗？

**解析。** 不一定。这里目标符号与干扰符号的词表范围不同，Value 投影可以压低干扰内容，让平均值仍保留目标信息。注意力学会聚焦是一种可能的解决方案，不是该任务的唯一解法。实验不能证明注意力机制对所有同类任务都必不可少。

**练习 2。** 为什么最后一个 Query 读取它自己不是“偷看答案”？

**解析。** 最后一个输入是 `问`，预测目标在输入之后。读到 `问` 只读到了当前已知输入，没有读到真实目标。掩码边界由输入与目标的移位关系决定。

**练习 3。** 把测试集换成训练集，准确率仍为 100%，少验证了什么？

**解析。** 少验证未见前缀上的规则推广。还需注意：即使训练和测试前缀不重复，也没有验证新长度或自然语言理解。
